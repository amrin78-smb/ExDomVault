# Database schema

Source of truth: `packages/database/src/schema/*.ts` (Drizzle). SQL migrations are generated into
`packages/database/migrations/` and committed. Never edit an applied migration; add a new one.

Conventions: UUID primary keys (`gen_random_uuid()`), `timestamptz` everywhere (UTC), PostgreSQL enums
for closed value sets, JSONB for extensible evidence with important attributes in typed columns,
`inet` for IP addresses.

## Workflow

```bash
# 1. Edit packages/database/src/schema/*.ts
npm run db:generate      # writes a new SQL migration (no DB connection needed)
npm run db:check         # drizzle-kit consistency check of the migration history
npm test                 # migration + constraint tests run against PGlite (in-process Postgres)
npm run db:migrate       # applies to the Neon branch in .env.local (direct URL)
```

`db:migrate` refuses to run when `NEON_BRANCH=production` unless `ALLOW_PRODUCTION_MIGRATION=yes`, and
refuses pooled (`-pooler`) URLs. Apply and verify on a development branch (`neon checkout dev --create`)
first. CI fails if the schema and committed migrations drift apart.

## Seeded scan profiles

Inserted by `0002_scan_job_lifecycle` with `ON CONFLICT (key) DO NOTHING` (existing rows are never
overwritten). All are version 1, enabled, `maxTargets` 50. Timeouts are connect / read / per target.

| Key        | Active | Checks                                                        | TCP ports                                                                                     | Timeouts            | Concurrency | Rate (/s) | `default_schedule` |
| ---------- | ------ | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ------------------- | ----------- | --------- | ------------------ |
| `passive`  | no     | `dns`, `rdap`                                                 | none                                                                                          | 3 s / 5 s / 60 s    | 4           | 5         | daily              |
| `quick`    | yes    | passive + `tls_certificate`, `http_availability`              | none                                                                                          | 5 s / 10 s / 120 s  | 4           | 2         | daily              |
| `standard` | yes    | quick + `http_headers`, `tcp_ports`, `service_identification` | 25 common service ports (e.g. 21, 22, 25, 80, 443, 3306, 3389, 5432, 6379, 8080, 8443, 27017) | 5 s / 10 s / 600 s  | 2           | 1         | weekly             |
| `deep`     | yes    | standard + `tls_configuration`                                | 56 ports (standard set plus e.g. 389, 636, 2375, 5601, 6443, 9090, 10250, 11211, 15672)       | 5 s / 15 s / 1800 s | 1           | 0.5       | monthly            |

`discovery` (seeded by `0006_asset_discovery`): passive, checks `discovery` only, no ports, 10 s / 60 s /
600 s, concurrency 4, 5 /s, `maxTargets` 1, `weekly`. It runs as `scan_jobs.job_type = 'discovery'` with
the apex as its only target, is not listed by `GET /scan-profiles` and cannot be requested through
`POST /domains/:id/scans`.

`passive` is scheduled automatically (daily) and `discovery` weekly (staggered, ≤ 50 jobs per run), by
the Cron Trigger. Active profiles cannot be
used while `ACTIVE_SCANNING_ENABLED` is off. Tiers: `quick` uses web-tier checks only (any public
address of an approved hostname); the `tcp_ports`, `service_identification` and `tls_configuration`
checks of `standard`/`deep` are network tier and only probe addresses inside approved networks; until
an administrator approves a network they are refused for every address (no probe is sent). `tls_configuration` is accepted but not run yet.

## Migration history

| Migration                   | Change                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0000_initial_schema`       | All design §5 tables.                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `0001_domain_authorisation` | `verification_method` gains `admin_attestation`, `challenge_status` gains `revoked`; `domain_verifications.challenge_hash` nullable + `reason`, `reference`; `domains.verification_method`, `verification_expires_at`; backfills verified domains as `dns_txt`. Checks avoid referencing the new enum values (they cannot be used in the transaction that adds them).                                                                                                     |
| `0002_scan_job_lifecycle`   | New tables `worker_credentials`, `worker_request_nonces`, `scan_job_results`; partial unique index `scan_jobs_one_active_per_domain_profile`; seeds the four `scan_profiles` rows (hand-added `INSERT … ON CONFLICT DO NOTHING`).                                                                                                                                                                                                                                         |
| `0003_approved_networks`    | New table `approved_networks` with checks (non-empty reason, expiry after creation, revoke reason) and the partial unique index `approved_networks_cidr_active_key`; foreign keys `created_by` / `revoked_by` → `users` (`ON DELETE SET NULL`). Must be applied before deploying the Milestone 6 application code (approved-networks API, job creation, claim, heartbeat and ingestion all read it).                                                                      |
| `0006_asset_discovery`      | `assets.decided_by` (FK → `users`, `ON DELETE SET NULL`), `decided_at`, `decision_reason`, `hosting_hint` JSONB, `wildcard_only` boolean (default false); `discovery_observations.wildcard` boolean (default false); seeds the `discovery` scan profile (`ON CONFLICT DO NOTHING`).                                                                                                                                                                                       |
| `0008_inventory_geo`        | `asset_ips.country_code` (nullable text, check `asset_ips_country_code_format`); indexes `port_observations_ip_port_time_idx` (`ip_address, port, protocol, observed_at DESC`) and `tls_observations_host_port_time_idx` (`hostname, port, observed_at DESC`) for the latest-per-key lookups of `GET /ports`, `/certificates`, `/attack-surface` and asset roles. Additive only; no new table, so no grant changes (the app role's default privileges cover new columns). |
