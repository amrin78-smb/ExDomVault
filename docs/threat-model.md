# Threat model

Scope: ExDomainVault as implemented at Milestone 6 — the Cloudflare Worker (SPA + `/api/v1`), Neon
PostgreSQL via Hyperdrive, and the home Linux scanning worker. Mitigations cite code; anything not
implemented is listed as residual risk. Scan-specific controls are detailed in
[`scan-safety.md`](scan-safety.md).

## Assets

| Asset                | Why it matters                                                                                                                                             | Where                                                                           |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Scan authority       | Verified domains, approved assets and approved networks decide what the home IP may contact. Misuse = attacking third parties from the owner's connection. | `domains`, `assets`, `approved_networks`, `scan_profiles`, job `scope_snapshot` |
| Worker signing key   | Ed25519 private key; whoever holds it (plus the Access token) can claim jobs and submit results.                                                           | `/etc/exdomainvault/worker.key` (root, 0600) → systemd credential dir           |
| Access service token | Gets requests past Cloudflare Access to the internal worker API.                                                                                           | `/etc/exdomainvault/worker.env` (0640 root:service group)                       |
| Application database | Inventory, observations, findings, users, audit log.                                                                                                       | Neon; reached only through Hyperdrive as `exdomainvault_app`                    |
| Audit log            | Evidence of privileged actions.                                                                                                                            | `audit_logs` (append-only for the app role)                                     |
| User sessions        | Cloudflare Access JWT / `CF_Authorization` cookie.                                                                                                         | Browser                                                                         |
| Home network         | LAN devices, router admin interfaces, the home public IP and its reputation.                                                                               | Behind the scanning host                                                        |

## Actors

| Actor                           | Capability assumed                                                                                                                              |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Malicious or compromised user   | Valid Access identity with one role: `viewer` (read), `asset_owner` (assigned assets), `analyst` (request/cancel scans), `admin` (everything).  |
| Insider admin                   | Full application rights, including domain authorisation and network approval.                                                                   |
| Compromised worker host         | Code execution as the service user, or root, on the home machine.                                                                               |
| Malicious target / DNS operator | Controls DNS answers, HTTP responses, TLS certificates and open services for a monitored domain (including a domain the attacker got verified). |
| Network attacker                | On-path between the worker and resolvers/targets, or between the internet and Cloudflare.                                                       |
| External attacker               | No credentials; can reach the public Worker hostname.                                                                                           |

## Trust boundaries

```text
 Browser ──(1)── Cloudflare Access ── Worker (SPA + /api/v1) ──(5)── Hyperdrive ── Neon
                                         ▲
 Home worker ──(2)── Access (service token) ┘    (signed, outbound HTTPS only)
     │
     ├──(3)── scan targets (web / network tier)
     └──(4)── DNS resolvers, IANA/registry RDAP
```

### (1) Browser ↔ Access ↔ Worker API

| Threat (STRIDE)            | Mitigation (implemented)                                                                                                                                                                                                                                                   | Residual risk                                                                                         |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| S: forged identity headers | `auth/cloudflare-access.ts` verifies the Access JWT (RS256 against team JWKS, issuer, AUD, expiry); identity headers never trusted; service tokens (no email) rejected for user routes. Unconfigured auth → 503 (`config.ts`). Dev auth refused when `APP_ENV=production`. | Compromise of the Access IdP or a user's IdP account.                                                 |
| E: role escalation         | `requirePermission(...)` on every authed route; role matrix `packages/shared/src/domain/permissions.ts`; inactive users refused.                                                                                                                                           | Object-level checks for `asset_owner` are endpoint-specific; review as endpoints are added.           |
| T: CSRF                    | `middleware/csrf.ts` `sameOriginWrites` (unsafe methods need same-origin `Origin`).                                                                                                                                                                                        | —                                                                                                     |
| T: malformed input         | zod schemas from `packages/shared` on every body/query; 300 KB body limit (`lib/validation.ts`).                                                                                                                                                                           | —                                                                                                     |
| I: error leakage           | `lib/errors.ts` envelope; unknown errors logged server-side, returned as generic `internal_error`.                                                                                                                                                                         | —                                                                                                     |
| D: request floods          | Cloudflare edge; Access in front.                                                                                                                                                                                                                                          | No per-user application rate limit or scan quota beyond one queued/active job per domain and profile. |

### (2) Home worker ↔ Access ↔ internal worker API

| Threat                       | Mitigation                                                                                                                                                                                                                                                                                     | Residual risk                                                                                                                       |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| S: impersonating the worker  | Two gates: Access Service Auth (service token) and `middleware/worker-auth.ts` Ed25519 signature over method, path+query, timestamp, nonce and body SHA-256. Only public keys stored; keys expire and can be revoked; workers can be disabled. User sessions never accepted on the worker API. | Theft of both the key and the token (same host).                                                                                    |
| T/R: replay                  | Timestamp within ±300 s; nonce unique per credential (`worker_request_nonces`, unique constraint), consumed after signature verification; nonces pruned after the window.                                                                                                                      | —                                                                                                                                   |
| T: job tampering             | Snapshot is server-side and immutable; the worker can only act on a job it holds (`lockOwnedJob`: worker id, attempt fencing token, status). Results for targets outside the job are rejected.                                                                                                 | —                                                                                                                                   |
| T: result forgery            | `services/observations.ts` re-validates every observation (target in job, time window, hostnames in domain, public addresses, profile ports, port addresses inside networks active at ingestion, active kinds only for active profiles). Idempotent `resultId`.                                | A holder of the worker credentials can still submit plausible but false values (certificate dates, port states) for jobs it claims. |
| D: worker floods the API     | 120 requests/min per credential, 1 MB body, ≤ 500 observations per submission.                                                                                                                                                                                                                 | —                                                                                                                                   |
| I: worker client misdirected | `app/client.py`: HTTPS required outside local development, redirects never followed, TLS verification on, response ≤ 1 MB.                                                                                                                                                                     | —                                                                                                                                   |

### (3) Worker ↔ scan targets

| Threat                                                   | Mitigation                                                                                                                                                                                                               | Residual risk                                                                                           |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| SSRF into the home LAN / loopback                        | `policy.ScopePolicy`: prohibited address tables, strict parsing, deny list; validation immediately before connect and pinning (`net.connect_tcp`); systemd `IPAddressDeny=` backstop (applies to Nmap too: same cgroup). | Home public IP is only refused if listed in `EXDV_DENY_NETWORKS`; the systemd filter does not cover it. |
| DNS rebinding / TOCTOU                                   | Connect to the validated literal address; CNAME chain change refused; Nmap `-n` with literal IPs.                                                                                                                        | —                                                                                                       |
| Redirect abuse                                           | `net.http_get` validates and pins every hop; IP literals, userinfo and non-HTTP schemes refused; ≤ 5 redirects; loops cut.                                                                                               | Scope is domain-level: redirects to any name in the domain are followed.                                |
| Malicious responses (slow drip, huge headers, XML bombs) | Per-hop deadline, header/body caps, Nmap output cap and DTD/entity screening, rlimits, systemd memory/task/CPU limits.                                                                                                   | —                                                                                                       |
| Hostile certificates / banners in evidence               | Certificates parsed locally with `cryptography`; header values truncated to printable ASCII; evidence ≤ 16 KB; React renders text (no HTML).                                                                             | —                                                                                                       |
| Harm to targets                                          | Non-destructive checks only; fixed Nmap template (`-sT`, `--max-rate`, `--max-retries 1`); per-job rate limiter and concurrency cap; max targets.                                                                        | Shared IPs scanned once per target; no cross-job rate budget; `-sV` may run `version` NSE scripts.      |

### (4) Worker ↔ resolvers and RDAP

| Threat              | Mitigation                                                                                           | Residual risk                                                                                        |
| ------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Spoofed DNS answers | Public resolvers by default; every answer re-validated against the address policy; answer cache off. | No DNSSEC validation; plain UDP/TCP DNS. A spoofed answer can steer web checks to another public IP. |
| Hostile RDAP server | HTTPS only, TLS verified, ≤ 3 HTTPS redirects, 1 MB cap, bootstrap from IANA.                        | RDAP redirects are not checked against the address policy (only the systemd filter applies).         |

### (5) Worker (Cloudflare) ↔ Neon via Hyperdrive

| Threat              | Mitigation                                                                                                                                                                                                            | Residual risk                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Credential exposure | Connection string exists only in the Hyperdrive configuration; least-privilege `exdomainvault_app` role (no superuser, no DDL, no role creation); migrations run separately as the Neon owner role from `.env.local`. | Neon/Cloudflare account compromise.                                    |
| Audit tampering     | `UPDATE`/`DELETE` revoked on `audit_logs` and `finding_status_history` for the app role; audit rows written in the same transaction as the change (`writeAudit`).                                                     | The Neon owner role can still alter history; no external log shipping. |

## Scenarios

| Scenario                                       | Path                                                                                      | Controls                                                                                                                                                                                                                                                             | Residual                                                                                                                                                             |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Scanning third parties via verification abuse  | Verify a domain you control, point its names at a victim's IPs, request an active scan.   | Network tier only reaches admin-approved networks (public, ≤ /16 or /32, reason, review date, audited). Web tier is browser-equivalent. Verification and authorisation are admin-only (`domains:verify`); active scans need `scans:request` (admin, analyst).        | Web checks (one handshake + GETs per hop, per address) can reach any public IP the domain's DNS names — owner-accepted. Admin can approve a victim network; audited. |
| SSRF into the home LAN via rebinding/redirects | DNS answer or redirect to `192.168.x.x`, `127.0.0.1`, `::ffff:10.0.0.1`, `0x7f.1`, NAT64… | Strict parsing and prohibited tables at resolve, at connect and per redirect; pinning; IP-literal redirects refused; systemd egress deny list.                                                                                                                       | The home public IP (router admin via hair-pinning) unless deny-listed; dynamic IP changes.                                                                           |
| Worker key theft                               | Read `worker.key` or `worker.env` on the host.                                            | Key root-owned 0600 at rest, delivered via `LoadCredential=` to a private credentials directory; `/etc/exdomainvault` inaccessible to the service; log redaction (`logging_config.redact`). Revoke key / disable worker in Settings; keys expire (default 365 days). | Root on the host obtains both key and token. Exposure window until revoked.                                                                                          |
| Service token theft                            | Read `worker.env`.                                                                        | Token alone only passes Access; the signature is still required. Rotate per `home-worker-setup.md` §12.                                                                                                                                                              | —                                                                                                                                                                    |
| Replay                                         | Resend a captured signed request.                                                         | Nonce uniqueness, timestamp window, body hash in signature; TLS to Cloudflare.                                                                                                                                                                                       | —                                                                                                                                                                    |
| Job tampering                                  | Compromised worker asks for different targets or ports.                                   | Worker can only claim jobs; scope comes from the server snapshot; the worker refuses snapshots whose targets leave the domain; results outside the job rejected; claim-time re-authorisation and network intersection.                                               | A compromised host can ignore its own policy and scan anything from the home IP — the application cannot prevent that; only host hardening can.                      |
| Result forgery                                 | Submit fabricated observations.                                                           | Ingestion re-validation (see boundary 2); fencing; idempotency.                                                                                                                                                                                                      | Values within the allowed shape are trusted; future findings derived from them inherit that trust.                                                                   |
| Audit evasion                                  | Privileged change without a trace.                                                        | Audited actions: verification/authorisation, `asset.approved`, `network.approved`/`revoked`, `scan.requested`/`cancelled`/`cancel_requested`/`refused`, worker and credential changes; same-transaction writes; append-only grants.                                  | Worker `scope_decision` logs live only in the home host's journal.                                                                                                   |
| Denial of service on the worker                | Slow servers, huge responses, many targets, CNAME loops.                                  | Deadlines, caps, `MAX_CNAME_HOPS`, one job at a time, systemd limits, lease expiry and bounded retries.                                                                                                                                                              | Many active jobs across domains queue serially; no per-user quota.                                                                                                   |
| Denial of service on targets                   | Abuse scans to flood a target.                                                            | Profile rates (≤ 50/s schema, seeded ≤ 5/s), Nmap `--max-rate` ≤ 100, one active job per domain/profile, max 50 targets.                                                                                                                                             | Repeated manual scans by an analyst are only limited by the one-job-at-a-time rule.                                                                                  |
| Data exposure via observations                 | A viewer reads sensitive evidence.                                                        | Observations need `domains:read`; cookies and bodies never stored; header values truncated; no secrets in logs.                                                                                                                                                      | Redirect URLs in `evidence.hops` may carry query-string tokens (truncated to 512 chars); `Server`/`X-Powered-By` disclose versions to all readers.                   |

## Operator responsibilities

- Put the home's public IPv4 (and IPv6 prefix) in `EXDV_DENY_NETWORKS` before enabling active scanning,
  and update it when the ISP changes the address.
- Keep both kill switches off until intended; enable `ACTIVE_SCANNING_ENABLED` and
  `EXDV_ACTIVE_SCANNING_ENABLED` deliberately and add only the needed profiles to `EXDV_PROFILES`.
- Rotate the worker key and the Access service token before expiry, and immediately on suspected
  exposure (revoke or disable first).
- Review approved networks and administrator domain authorisations before their review dates; revoke
  what is no longer owned.
- Keep the host, Python dependencies and Nmap patched; do not run untrusted workloads (e.g. a GitHub
  self-hosted runner) on the scanning host.
- Periodically review the audit log and the worker journal (`scope_decision` with `allowed: false`).
